O que é isso?

O objetivo do projeto

Antes de ver o código, entenda o que estamos construindo — e por que cada peça existe.

Conceito 01

🌐 O que é uma API?

API é como um garçom num restaurante. Você (o cliente) faz o pedido, ele leva até a cozinha (servidor) e traz o resultado. Você nunca entra na cozinha — só pede e recebe.

Conceito 02

📋 O que é REST?

REST é um conjunto de regras para que a API funcione de forma organizada. Define que usamos verbos como GET (buscar), POST (criar), PUT (atualizar) e DELETE (apagar).

Conceito 03

📦 O que este projeto faz?

É um sistema de lista de tarefas (To-Do). Você pode criar tarefas, listar todas, marcar como concluída ou apagar. Tudo via chamadas HTTP — como o seu aplicativo de celular faz com um servidor.

Conceito 04

🧠 Por que estudar isso?

Toda aplicação moderna — Instagram, iFood, Nubank — tem um backend com APIs. Aprender a construir uma é o primeiro passo para trabalhar como desenvolvedor full-stack ou backend.

Tech Stack

As ferramentas usadas

Cada tecnologia tem um papel específico. Aqui está o que cada uma faz — em linguagem simples.

🟢
Node.js
Permite rodar JavaScript fora do navegador — diretamente no servidor. É o "motor" que faz a API funcionar.
Analogia: É como instalar um motor num carro. O JavaScript seria a gasolina; o Node.js, o motor que a queima.
🔷
TypeScript
É JavaScript com "regras extras". Você define o tipo de cada dado (texto, número, sim/não) e o TypeScript avisa quando algo está errado antes mesmo de rodar.
Analogia: É como escrever um formulário com campos obrigatórios. Não dá pra enviar com o nome em branco.
⚡
Express
É o framework que cria e organiza as rotas da API. Sem ele, você teria que escrever muito mais código para ouvir requisições HTTP.
Analogia: É como uma plataforma de delivery já pronta. Você só cadastra os produtos (rotas), eles cuidam da entrega.
🛡️
Zod
Valida os dados que chegam na API. Se alguém tentar criar uma tarefa sem título, o Zod rejeita com uma mensagem clara antes de qualquer coisa errada acontecer.
Analogia: É o segurança da balada. Ele verifica se você está no lista antes de deixar entrar.

src/server.ts
import express from "express"
import taskRoutes from "./routes/task.routes"
import { notFoundHandler } from "./middlewares/errorHandler"

const app = express()
const PORT = 3000

// middleware pra conseguir ler o json do body
app.use(express.json())

// rota inicial so pra testar se ta funcionando
app.get("/", (req, res) => {
  res.json({ message: "api funcionando" })
})

// rotas das tarefas
app.use("/api/v1/tasks", taskRoutes)

// rota nao encontrada - tem que ficar no final
app.use(notFoundHandler)

// subir o servidor
app.listen(PORT, () => {
  console.log("servidor rodando na porta " + PORT)
})
📦

import express from "express"

Importa o Express — a biblioteca que cria o servidor HTTP. Sem essa linha, nada funciona.

🏗️

const app = express()

Cria a instância do servidor. É como abrir a porta da sua loja — a partir daqui, você configura o que acontece lá dentro.

🔧

app.use(express.json())

Ensina o servidor a ler JSON. Sem isso, o req.body vem vazio — você não consegue ler os dados enviados pelo cliente.

🚪

app.use("/api/v1/tasks", taskRoutes)

Conecta todas as rotas de tarefas ao prefixo /api/v1/tasks. Organização: separa as rotas em arquivos diferentes.

👂

app.listen(PORT, ...)

O servidor começa a "ouvir" por requisições na porta 3000. É como ligar o rádio numa frequência específica.

src/routes/task.routes.ts
import { Router } from "express"
import { listTasks, findTask, addTask,
         editTask, toggleStatus, removeTask }
  from "../controllers/task.controller"

const router = Router()

// cada linha conecta um verbo HTTP + caminho -> funcao
router.get("/", listTasks)           // GET  /tasks
router.get("/:id", findTask)         // GET  /tasks/:id
router.post("/", addTask)            // POST /tasks
router.put("/:id", editTask)         // PUT  /tasks/:id
router.patch("/:id/toggle", toggleStatus) // PATCH /tasks/:id/toggle
router.delete("/:id", removeTask)    // DELETE /tasks/:id

export default router
🗺️

Router()

Cria um "mini-app" apenas para as rotas de tarefas. Assim você pode importar e montar em qualquer prefixo no server.ts.

🔍

router.get("/:id", findTask)

O :id é um parâmetro dinâmico. Se você chamar /tasks/abc123, o valor abc123 fica em req.params.id.

📮

Verbos HTTP (GET, POST, PUT...)

Cada verbo tem um significado: GET = buscar dados, POST = criar novo, PUT = substituir, PATCH = atualizar parte, DELETE = apagar.

src/schemas/task.schema.ts
import { z } from "zod"

// define como os dados precisam chegar para criar uma tarefa
export const createTaskSchema = z.object({

  title: z.string()
    .min(1, "titulo nao pode ser vazio")
    .max(100, "titulo muito grande"),

  description: z.string()
    .max(500, "descricao muito grande")
    .optional(),    // campo nao obrigatorio

  priority: z.string().optional()

})

// --- quando usamos ---
// const body = createTaskSchema.parse(req.body)
// se os dados forem invalidos, o Zod lanca um erro automaticamente
// com a mensagem que a gente escreveu acima
📐

z.object({...})

Define o "molde" dos dados esperados. É como um formulário: cada campo tem regras sobre o que é aceito.

📏

.min(1) e .max(100)

Define limites de tamanho para textos. .min(1) garante que o campo não está vazio. .max(100) evita textos enormes.

❓

.optional()

Torna o campo não obrigatório. Sem isso, se o cliente não enviar o campo, o Zod retorna erro automaticamente.

🚀

.parse(req.body)

Executa a validação. Se os dados estiverem certos, retorna os dados limpos. Se não, lança um erro com a mensagem personalizada.

src/services/task.service.ts
import { v4 as uuidv4 } from "uuid"
import { Task } from "../types/task.types"

// array que guarda as tarefas na memoria
// quando o servidor reiniciar perde tudo, mas tudo bem por enquanto
let tasks: Task[] = []

// criar uma nova tarefa
export function createTask(title: string,
                           description: string,
                           priority: string) {
  let newTask: Task = {
    id: uuidv4(),          // gera um id unico automatico
    title: title,
    description: description,
    completed: false,       // sempre começa false
    priority: priority,
    createdAt: new Date().toISOString(),
    updatedAt: new Date().toISOString()
  }

  tasks.push(newTask)   // adiciona no array
  return newTask        // retorna a tarefa criada
}
🗄️

let tasks: Task[] = []

O "banco de dados" da aplicação por enquanto. Um array simples em memória. Perde tudo quando o servidor reinicia — mas é ótimo para aprender.

🎲

uuidv4()

Gera um ID único aleatório tipo a4b2c.... UUID = Universally Unique Identifier. Garante que nunca haverá dois iguais.

📅

new Date().toISOString()

Captura o momento exato de criação e converte para o formato internacional de data: 2024-01-15T10:30:00.000Z.

➕

tasks.push(newTask)

Adiciona a nova tarefa ao final do array — como empurrar um papel para o fim de uma pilha. Depois disso, ela aparece no GET de todas as tarefas.

src/controllers/task.controller.ts
import { Request, Response } from "express"
import { ZodError } from "zod"
import { createTaskSchema } from "../schemas/task.schema"
import { createTask } from "../services/task.service"

export function addTask(req: Request, res: Response) {
  try {
    // 1) validar o body com zod
    let body: any
    try {
      body = createTaskSchema.parse(req.body)
    } catch (err) {
      if (err instanceof ZodError) {
        let errorMessages = []
        for (let i = 0; i < err.issues.length; i++) {
          errorMessages.push(err.issues[i].message)
        }
        res.status(400).json({
          success: false,
          message: "dados invalidos",
          errors: errorMessages
        })
        return  // para a execucao aqui
      }
    }

    // 2) criar a tarefa no service
    let task = createTask(body.title, body.description, body.priority)

    // 3) responder com 201 (criado com sucesso)
    res.status(201).json({ success: true, data: task })

  } catch (err) {
    res.status(500).json({ success: false, message: "erro no servidor" })
  }
}
📥

Request e Response

req = o que chegou do cliente (body, params, headers). res = o que você vai responder. Sempre trabalhamos com esses dois.

🔒

try/catch

Protege o código de travamentos. Se algo der errado dentro do try, o catch captura e manda uma resposta de erro em vez de travar o servidor.

🔢

res.status(201)

HTTP status codes: 200 = OK, 201 = Criado, 400 = Dados inválidos, 404 = Não encontrado, 500 = Erro interno. São a "linguagem" do HTTP.

↩️

return (após res.json)

Para a execução da função após enviar a resposta de erro. Sem o return, o código continuaria executando e tentaria enviar duas respostas — causando um crash.

Todos os endpoints

GET /api/v1/tasks Retorna a lista completa de tarefas

Termos que você precisa conhecer

Palavras que aparecem todo dia no mundo backend — explicadas de forma simples.

🏗️

Interface (TypeScript)

Define o "formato" de um objeto. É como uma planta de apartamento: diz quais cômodos (campos) ele tem e de que tipo são.

interface Task { id: string; title: string }
🔄

CRUD

Sigla para as 4 operações básicas de qualquer sistema: Create, Read, Update, Delete. Todo sistema de dados precisa dessas 4.

POST / GET / PUT / DELETE
📨

Middleware

Código que roda entre a requisição chegar e a resposta sair. O express.json() é um middleware — ele "traduz" o body antes do seu código vê-lo.

app.use(express.json())
🎁

JSON

Formato de texto para trocar dados entre sistemas. É como uma embalagem padronizada — qualquer linguagem consegue abrir e ler.

{"success": true, "data": [...]}
🔢

Status Code HTTP

Número que indica o resultado de uma requisição. 200 = sucesso, 201 = criado, 400 = erro do cliente, 404 = não encontrado, 500 = erro do servidor.

res.status(201).json({...})
🎲

UUID

ID único gerado automaticamente. Garante que cada tarefa tem um identificador impossível de repetir — mesmo que você crie milhões de tarefas.

id: "a4f2b1c3-d5e6-..."
